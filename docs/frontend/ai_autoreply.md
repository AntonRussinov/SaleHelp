## 1. Статус аккаунта

Основной источник данных для хедера/дашборда: тариф, AI-баланс, количество магазинов.

> Рекомендуется загружать при старте приложения (после логина), сохранять в глобальный стейт и обновлять после действий, влияющих на баланс (использование AI, добавление магазина).

### `GET /v1/account/status`

**Ответ `200`:**
```json
{
  "subscription": {
    "tier": "business",
    "status": "active",
    "expires_at": "2026-07-11T00:00:00Z",
    "days_remaining": 55,
    "max_shops": 2,
    "extra_shops": 0,
    "ai_quota": 200,
    "ai_used": 47,
    "ai_resets_at": "2026-06-01T00:00:00Z"
  },
  "ai_balance": {
    "subscription_remaining": 153,
    "packages_remaining": 50,
    "total_available": 203
  },
  "shops_count": 1,
  "shops_limit": 2
}
```

**Если подписки нет** (триал истёк или ещё не создан):
```json
{
  "subscription": null,
  "ai_balance": {
    "subscription_remaining": 0,
    "packages_remaining": 0,
    "total_available": 0
  },
  "shops_count": 1,
  "shops_limit": 0
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `subscription` | object\|null | `null` если нет активной подписки |
| `subscription.tier` | string | `trial`, `start`, `business`, `pro` |
| `subscription.status` | string | `trial`, `active`, `cancelled`, `expired` |
| `subscription.expires_at` | datetime | Когда истекает подписка |
| `subscription.days_remaining` | int | Дней до истечения (0 если просрочена) |
| `subscription.max_shops` | int | Базовый лимит магазинов по тарифу |
| `subscription.extra_shops` | int | Доп. магазины (куплены отдельно) |
| `subscription.ai_quota` | int | Лимит AI-ответов в месяц |
| `subscription.ai_used` | int | Использовано в текущем месяце |
| `subscription.ai_resets_at` | datetime | Дата следующего сброса квоты |
| `ai_balance.subscription_remaining` | int | Остаток квоты по подписке |
| `ai_balance.packages_remaining` | int | Остаток купленных пакетов AI |
| `ai_balance.total_available` | int | Суммарный доступный баланс |
| `shops_count` | int | Сколько магазинов у пользователя |
| `shops_limit` | int | Лимит (`max_shops + extra_shops`), 0 если нет подписки |

**Что показывать на UI:**
- Триал-баннер: `subscription.status == "trial"` → отсчёт `days_remaining`
- AI-баланс в хедере: `ai_balance.total_available` из `X` (`ai_quota`)
- Кнопка «Добавить магазин»: заблокировать если `shops_count >= shops_limit`
- Плашка «Подписка истекает»: `days_remaining <= 7`
- Предупреждение о квоте: `subscription_remaining < 20` (или < 10%)

## 2. Статус подписки по магазину

Используется для: AI-настроек конкретного магазина, блокировки фич по тарифу внутри магазина.

> Если уже загружен `/account/status` — дублировать этот запрос не нужно: данные по тарифу одинаковы. Используй его только если нужна проверка владения магазином.

### `GET /v1/shop/{shopId}/subscription/status`

Возвращает текущую активную подписку пользователя, владеющего этим магазином.

**Параметры пути:** `shopId` — ID магазина (integer).

**Ответ `200`:**
```json
{
  "has_active_subscription": true,
  "tier": "business",
  "status": "active",
  "expires_at": "2026-06-11T00:00:00Z",
  "ai_quota": 200,
  "ai_used": 47,
  "max_shops": 2,
  "allowed_telegram_chats": 3
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `has_active_subscription` | bool | Есть ли активная/триальная подписка |
| `tier` | string\|null | `trial`, `start`, `business`, `pro` |
| `status` | string\|null | `trial`, `active`, `cancelled`, `expired` |
| `expires_at` | datetime\|null | Когда истекает подписка |
| `ai_quota` | int | Лимит AI-ответов в месяц (0 = нет AI) |
| `ai_used` | int | Использовано AI-ответов в этом месяце |
| `max_shops` | int | Максимум магазинов по тарифу |
| `allowed_telegram_chats` | int | Доступно Telegram-эндпоинтов |

**Что показывать на UI:**
- `ai_quota - ai_used` → остаток AI-ответов в месяц
- Прогресс-бар: `ai_used / ai_quota * 100%`
- Если `ai_quota == 0` → AI недоступен, показать плашку апгрейда
- Если `has_active_subscription == false` → пробная версия закончилась или нет подписки
- `tier == "trial"` → показывать триал-баннер с обратным отсчётом до `expires_at`

## 3. AI-настройки: основные параметры

### `GET /v1/shops/{shopId}/ai-settings`

Возвращает полные настройки AI для магазина **вместе с правилами и шаблонами** в одном запросе.

> Если настройки ещё не создавались — возвращает дефолтные значения (не 404). Это значит, что фронт может показывать форму сразу, без предварительной проверки.

**Ответ `200`:**
```json
{
  "id": 5,
  "shopId": 12,
  "isActive": true,
  "toneOfVoice": "friendly",
  "responseLength": "medium",
  "addressing": "vy",
  "emojiMode": "minimal",
  "brandName": "МойБренд",
  "brandDescription": "Производим эко-товары для дома",
  "representativeName": "Иван",
  "signature": "С уважением, команда МойБренд",
  "rules": [
    { "id": 1, "ruleType": "rule",           "ruleText": "Всегда упоминай гарантию 1 год", "orderIndex": 0 },
    { "id": 2, "ruleType": "forbidden_word", "ruleText": "дешёвый",                        "orderIndex": 0 }
  ],
  "templates": [
    { "id": 1, "category": "positive", "customPrompt": "",                             "toneVoiceOverride": "",          "enabled": true },
    { "id": 2, "category": "negative", "customPrompt": "Обязательно предложи звонок", "toneVoiceOverride": "empathic",  "enabled": true }
  ],
  "createdAt": "2026-05-10T12:00:00Z",
  "updatedAt": "2026-05-17T09:00:00Z"
}
```

**Дефолтные значения** (когда настройки ещё не создавались, `id` будет `0`):
```json
{
  "id": 0,
  "shopId": 12,
  "isActive": false,
  "toneOfVoice": "friendly",
  "responseLength": "medium",
  "addressing": "vy",
  "emojiMode": "minimal",
  "brandName": "",
  "brandDescription": "",
  "representativeName": "",
  "signature": "",
  "rules": [],
  "templates": []
}
```

---

### `PUT /v1/shops/{shopId}/ai-settings`

Создаёт или обновляет основные параметры (все поля, кроме правил и шаблонов — они управляются отдельными эндпоинтами).

**Тело запроса:**
```json
{
  "isActive": true,
  "toneOfVoice": "friendly",
  "responseLength": "medium",
  "addressing": "vy",
  "emojiMode": "minimal",
  "brandName": "МойБренд",
  "brandDescription": "Производим эко-товары для дома",
  "representativeName": "Иван",
  "signature": "С уважением, команда МойБренд"
}
```

| Поле | Обязательно | Допустимые значения |
|------|-------------|-------------------|
| `isActive` | да | `true` / `false` |
| `toneOfVoice` | да | `standard`, `friendly`, `official`, `empathic`, `minimalist` |
| `responseLength` | да | `short` (≤200 симв.), `medium` (≤400 симв.), `long` (≤600 симв.) |
| `addressing` | да | `vy` (обращение на «вы»), `ty` (на «ты») |
| `emojiMode` | да | `none`, `minimal` (1–2 эмодзи), `expressive` (2–4 эмодзи) |
| `brandName` | нет | строка, max 100 симв. |
| `brandDescription` | нет | строка, max 500 симв. |
| `representativeName` | нет | строка, max 50 симв. |
| `signature` | нет | строка, max 200 симв. |

**Ответ `200`:** полный объект `AISettingsResponse` (как в GET выше).

**Важно для UX:**
- Это один PUT на весь блок настроек — нет patch-обновления отдельных полей.
- Всегда отправлять полный объект, даже если изменилось только одно поле.
- Тумблер `isActive` включает/выключает автоответы для всего магазина.

## 4. Правила бренда и запрещённые слова

Правила делятся на два типа, различаемых полем `ruleType`:

| `ruleType` | Назначение | Как используется в AI |
|------------|-----------|----------------------|
| `rule` | Доп. инструкция для ответа | «Всегда упоминай гарантию», «Не предлагай скидки» |
| `forbidden_word` | Слово/фраза, которую нельзя использовать | «дешёвый», «брак» |

### Лимиты по тарифу

| Тариф | Макс. правил (rule + forbidden_word суммарно) |
|-------|----------------------------------------------|
| `trial` | 2 |
| `start` | 0 (раздел недоступен) |
| `business` | 2 |
| `pro` | 5 |

> При попытке добавить правило сверх лимита сервер вернёт `403` с `code: "rules_limit_reached"`.
> Если тариф `start` — раздел правил показывать как заблокированный с предложением апгрейда.

---

### `POST /v1/shops/{shopId}/ai-settings/rules`

Добавляет одно правило.

**Тело запроса:**
```json
{
  "ruleType": "rule",
  "ruleText": "Всегда упоминай гарантию 1 год",
  "orderIndex": 0
}
```

| Поле | Обязательно | Допустимые значения |
|------|-------------|-------------------|
| `ruleType` | да | `rule`, `forbidden_word` |
| `ruleText` | да | строка, max 200 симв. |
| `orderIndex` | нет | int ≥ 0, для сортировки в интерфейсе |

**Ответ `201`:**
```json
{
  "id": 7,
  "ruleType": "rule",
  "ruleText": "Всегда упоминай гарантию 1 год",
  "orderIndex": 0
}
```

---

### `PUT /v1/shops/{shopId}/ai-settings/rules/{ruleId}`

Обновляет существующее правило.

**Тело запроса:** те же поля, что и при создании (`ruleType`, `ruleText`, `orderIndex`).

**Ответ `200`:** обновлённый объект правила.

---

### `DELETE /v1/shops/{shopId}/ai-settings/rules/{ruleId}`

Удаляет правило.

**Ответ `204 No Content`** — тело пустое.

## 5. Шаблоны по категориям отзыва

Шаблоны позволяют задать дополнительные инструкции и/или другой тон для каждой категории отзыва.

| `category` | Когда применяется |
|------------|------------------|
| `positive` | Рейтинг 4–5 звёзд |
| `neutral` | Рейтинг 3 звезды |
| `negative` | Рейтинг 1–2 звезды |

### `PUT /v1/shops/{shopId}/ai-settings/templates/{category}`

Создаёт или обновляет шаблон для категории. `{category}` в пути — одно из: `positive`, `neutral`, `negative`.

**Тело запроса:**
```json
{
  "customPrompt": "Обязательно упомяни программу лояльности",
  "toneVoiceOverride": "empathic",
  "enabled": true
}
```

| Поле | Обязательно | Допустимые значения |
|------|-------------|-------------------|
| `customPrompt` | нет | строка, max 500 симв. Дополнительные инструкции AI именно для этой категории |
| `toneVoiceOverride` | нет | `standard`, `friendly`, `official`, `empathic`, `minimalist` — перекрывает базовый тон только для этой категории |
| `enabled` | нет | `true`/`false`. Если `false` — шаблон сохранён но не применяется |

**Ответ `200`:**
```json
{
  "id": 3,
  "category": "negative",
  "customPrompt": "Обязательно упомяни программу лояльности",
  "toneVoiceOverride": "empathic",
  "enabled": true
}
```

**Важно для UX:**
- Поля `customPrompt` и `toneVoiceOverride` можно оставить пустыми — шаблон всё равно существует (через `enabled` можно управлять).
- `toneVoiceOverride` — доступен на всех тарифах (trial, business, pro). Если пустая строка — используется базовый тон из настроек.
- Шаблоны не нужно создавать заранее — PUT создаёт или обновляет.

## 6. Управление аккаунтом

### `DELETE /v1/account`

Необратимо удаляет аккаунт пользователя, все его магазины, AI-настройки и остальные данные (каскадно через БД).

**Тело запроса:**
```json
{ "confirmation": "DELETE" }
```

Поле `confirmation` обязательно и должно содержать строку `"DELETE"` — это защита от случайного вызова.

**Ответ `204 No Content`** — тело пустое, сессия должна быть завершена на клиенте.

**Ошибки:**

| Статус | Когда |
|--------|-------|
| `400` | `confirmation` не равно `"DELETE"` или тело не передано |
| `401` | Не авторизован |
| `500` | Внутренняя ошибка |

**UX-рекомендации:**
- Показывать двухшаговое подтверждение: первый клик → предупреждение об необратимости; второй клик → отправка запроса.
- После `204` — разлогинить пользователя (удалить JWT из storage) и редиректить на главную/login.
- На странице настроек аккаунта / профиля.

## 7. UX-сценарии

### 7.1. Первое открытие страницы AI-настроек

```
GET /v1/shops/{shopId}/ai-settings          → получить настройки + правила + шаблоны
GET /v1/shop/{shopId}/subscription/status   → получить тариф для gating UI
```

Делать оба запроса параллельно. Отображать форму сразу — GET настроек всегда возвращает данные (пусть и дефолтные).

### 7.2. Пользователь сохраняет основные настройки

```
PUT /v1/shops/{shopId}/ai-settings   { все поля формы }
```

Одним запросом. Показать success-тост.

### 7.3. Пользователь добавляет правило

1. Проверить лимит по тарифу (фронт уже знает из `subscription/status` + таблицы лимитов).
2. `POST /v1/shops/{shopId}/ai-settings/rules   { ruleType, ruleText }`
3. Добавить новое правило в локальный стейт (не перезапрашивать весь GET).
4. При `403` с `code: "rules_limit_reached"` → показать модал с предложением апгрейда тарифа.

### 7.4. Пользователь редактирует правило inline

```
PUT /v1/shops/{shopId}/ai-settings/rules/{ruleId}   { ruleType, ruleText, orderIndex }
```

Обновлять только при потере фокуса или явном сохранении (не на каждый символ).

### 7.5. Пользователь настраивает шаблон для «негативных» отзывов

```
PUT /v1/shops/{shopId}/ai-settings/templates/negative   { customPrompt, toneVoiceOverride, enabled }
```

Шаблоны можно редактировать независимо. Тип category передаётся в URL, не в теле.

### 7.6. Включение/выключение автоответов

```
PUT /v1/shops/{shopId}/ai-settings   { ...текущие настройки..., "isActive": true/false }
```

Тумблер on/off — всегда отправляем полный объект с `isActive` изменённым.

### 7.7. Загрузка статуса аккаунта при старте

```
GET /v1/account/status   → сохранить в глобальный стейт
```

Делать при инициализации (после проверки JWT). Этих данных хватает для:
- Хедера (тариф, баланс AI)
- Кнопки «Добавить магазин» (заблокирована если лимит)
- Триал-баннера
- Gating на странице AI-настроек

### 7.8. Отображение остатка квоты

Из `subscription/status`:
- `ai_quota = 200`, `ai_used = 47` → показать `153 / 200` или прогресс-бар
- `ai_quota = 0` → AI недоступен для этого тарифа
- Квота сбрасывается 1-го числа каждого месяца

## 8. Ограничения по тарифам

Таблица фич AI по тарифам для gating на фронте:

| Фича | `start` | `trial` | `business` | `pro` |
|------|---------|---------|------------|-------|
| AI-автоответы вкл/выкл | ✅ | ✅ | ✅ | ✅ |
| AI-ответов в месяц | 50 | 200 | 200 | 800 |
| Тон, длина, обращение, эмодзи | ✅ | ✅ | ✅ | ✅ |
| Бренд, описание, подпись | ✅ | ✅ | ✅ | ✅ |
| Шаблоны по категориям | ✅ | ✅ | ✅ | ✅ |
| Tone override по категории | ✅ | ✅ | ✅ | ✅ |
| Правила бренда | ❌ | ✅ (до 2) | ✅ (до 2) | ✅ (до 5) |
| Запрещённые слова | ❌ | ✅ (до 2 вместе с правилами) | ✅ (до 2) | ✅ (до 5) |

> Лимит правил — суммарный для `rule` + `forbidden_word`.
> Для тарифа `start`: раздел правил показывать с замком и предложением апгрейда.

**Как проверять тариф на фронте:**
```js
const tier = subscriptionStatus.tier ?? 'start'
const maxRules = { trial: 2, start: 0, business: 2, pro: 5 }[tier] ?? 0
const canAddRule = currentRulesCount < maxRules
```

## 9. Обработка ошибок

Все ошибки возвращаются в формате:
```json
{ "error": "человекочитаемое сообщение", "code": "machine_readable_code" }
```
или просто:
```json
{ "error": "текст" }
```

| HTTP-статус | `code` | Когда | Что показать |
|-------------|--------|-------|-------------|
| `400` | — | Невалидные данные (пустой `toneOfVoice`, недопустимое значение) | Подсветить поле, показать ошибку |
| `401` | — | JWT не передан или истёк | Редирект на login |
| `403` | `shop_limit_reached` | Лимит магазинов по тарифу | «Достигнут лимит магазинов» |
| `403` | `rules_limit_reached` | Превышен лимит правил | «Лимит правил исчерпан, нужен Pro» |
| `403` | `rules_not_available` | Тариф Start — правила недоступны | «Доступно с тарифа Business» |
| `403` | — | Чужой магазин | Показать 403-страницу |
| `404` | — | Правило с таким ID не найдено | «Правило не найдено» |
| `500` | — | Внутренняя ошибка | Общий тост «Что-то пошло не так» |

## 10. Справочники

### `toneOfVoice` — тон ответов

| Значение | Описание для UI |
|----------|----------------|
| `standard` | Стандартный — вежливо и нейтрально |
| `friendly` | Дружелюбный — тепло и по-человечески |
| `official` | Официальный — строго, акцент на качестве |
| `empathic` | Эмпатичный — с вниманием к чувствам клиента |
| `minimalist` | Минималистичный — очень коротко и по делу |

### `responseLength` — длина ответа

| Значение | Лимит | Описание |
|----------|-------|----------|
| `short` | ≤200 символов | Краткий |
| `medium` | ≤400 символов | Стандартный (рекомендуется) |
| `long` | ≤600 символов | Развёрнутый |

### `addressing` — обращение

| Значение | Описание |
|----------|----------|
| `vy` | На «вы» (рекомендуется для большинства магазинов) |
| `ty` | На «ты» |

### `emojiMode` — режим эмодзи

| Значение | Описание |
|----------|----------|
| `none` | Без эмодзи |
| `minimal` | До 1–2 уместных эмодзи |
| `expressive` | До 2–4 эмодзи |

### `ruleType` — тип правила

| Значение | Описание | Пример |
|----------|----------|--------|
| `rule` | Доп. инструкция | «Всегда упоминай гарантию 1 год» |
| `forbidden_word` | Запрещённое слово/фраза | «дешёвый», «проблема с качеством» |

### `category` — категория шаблона

| Значение | Применяется | Описание |
|----------|-------------|----------|
| `positive` | Рейтинг 4–5★ | Позитивный отзыв |
| `neutral` | Рейтинг 3★ | Нейтральный отзыв |
| `negative` | Рейтинг 1–2★ | Негативный отзыв |

## Маршруты — сводная таблица

### Аккаунт

| Метод | URL | Описание | Auth |

### Подписка

| Метод | URL | Описание | Auth |
|-------|-----|----------|------|
| `GET` | `/v1/shop/{shopId}/subscription/status` | Статус подписки по магазину | JWT |

### AI-настройки

| Метод | URL | Описание | Auth |
|-------|-----|----------|------|
| `GET` | `/v1/shops/{shopId}/ai-settings` | Все AI-настройки + правила + шаблоны | JWT |
| `PUT` | `/v1/shops/{shopId}/ai-settings` | Сохранить основные параметры | JWT |
| `POST` | `/v1/shops/{shopId}/ai-settings/rules` | Добавить правило | JWT |
| `PUT` | `/v1/shops/{shopId}/ai-settings/rules/{ruleId}` | Обновить правило | JWT |
| `DELETE` | `/v1/shops/{shopId}/ai-settings/rules/{ruleId}` | Удалить правило | JWT |
| `PUT` | `/v1/shops/{shopId}/ai-settings/templates/{category}` | Сохранить шаблон категории | JWT |

> Обрати внимание на разницу в URL: `/v1/shop/{shopId}/...` (без `s`) — роут статуса подписки; `/v1/shops/{shopId}/...` (с `s`) — все AI-настройки.
